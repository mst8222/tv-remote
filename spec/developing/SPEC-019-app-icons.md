# SPEC-019 应用快捷方式显示真实图标

## 元信息

- 状态：developing
- 创建：2026-10-22
- 更新：2026-10-22（开工：spec 与手工清单已建立，移入 developing）
- 优先级：medium

## 变更记录

- 2026-10-22 创建：用户提出应用快捷版块目前只显示首字圆形占位，
  希望把盒子端应用的真实图标读取上来。确定方案为新增 `ICON` 协议命令按包名
  懒加载，不把图标塞进 `LIST` 载荷。

## 背景与目标

SPEC-016 让应用卡动态列出盒子全部第三方应用，但手机端只用「应用名首字 + 圆形底色」
占位（`appCell`），在应用较多时辨识度差。盒子端 `PackageManager` 本来就有每个应用的
图标，可以通过现有直连协议取回。

目标：应用快捷版块显示与盒子端一致的图标，同时保持列表加载速度和断网可用性。

## 功能需求（FR）

- FR-19-1 协议新增 `ICON <token> <包名>`：
  - 成功返回 `OK <base64(UTF-8 无关，PNG 二进制)>`，图标渲染为 144x144 PNG；
  - 包名缺失返回 `ERR arg`；包名不存在或图标渲染失败返回 `ERR arg`；
  - token 错误返回 `ERR auth`（沿用现有「认证先于参数」顺序）；
  - 不受无障碍开关影响（与 `LIST` 一致）。
- FR-19-2 手机端应用卡每个格子先显示「首字圆形占位」，异步请求 `ICON` 后
  用真实图标替换；请求失败保持占位，不影响名称显示与点击启动。
- FR-19-3 图标按「当前设备 IP + 包名」缓存在内存中：同一设备重建应用卡
  （如再次刷新列表）不重复请求；切换设备后不会串用上一台盒子的图标。
- FR-19-4 仅直连模式请求图标（蓝牙模式没有应用列表通道，应用卡隐藏）。
- FR-19-5 「设置」项同样向盒子请求 `com.android.settings` 的图标；
  盒子没有该包时保持首字占位。

## 非功能需求（NFR）

- NFR-19-1 单个图标 PNG 常规不超过 20KB，Base64 后不超过约 27KB，单行协议可承受；
- NFR-19-2 图标请求在 worker 线程执行，不阻塞 UI；
- NFR-19-3 单次图标请求超时 6 秒，失败静默回落到占位；
- NFR-19-4 图标内存缓存只保留当前会话，进程重启后重新加载（不落盘）。

## 验收标准（AC）

- AC-1 H96 直连：应用卡各格显示盒子端真实图标，与盒子桌面上的图标一致。
- AC-2 `ICON <token> 不存在的包` 返回 `ERR arg`。
- AC-3 `ICON <错误 token> <包名>` 返回 `ERR auth`。
- AC-4 盒子停服时应用卡仍按缓存渲染，图标保持首字占位，点击提示不变。
- AC-5 切换到另一台盒子后应用卡图标不出现上一台盒子的图标。
- AC-6 `powershell -File tests\protocol\run.ps1` 全部通过（新增 ICON 用例）。

## 边界与已知限制

- 图标固定按 144x144 渲染，手机端 56dp 图标位在高密度屏会有轻微放大；
- 自适应图标（AdaptiveIconDrawable）直接绘制到 144x144 画布，不做圆形裁切，
  保留盒子端原始外观；
- 应用数量较多时逐个懒加载，图标会分批出现（不阻塞列表先显示）；
- 图标不落盘，冷启动/换设备后需重新拉取；
- 蓝牙模式无图标（应用卡本身只在直连模式可用）。
