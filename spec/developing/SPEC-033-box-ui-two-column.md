# SPEC-033 盒端界面宽屏双栏与二维码前置

## 元信息

- 状态：developing
- 创建：2026-10-22
- 更新：2026-10-22（布局修订）
- 优先级：high

## 变更记录

- 2026-10-22 创建并实现：用户在电视上查看 Fold3 盒子端界面时，二维码在首屏之外，
  向下滚动后界面又跳回顶部，无法扫码。改为宽屏（>=720dp）左右两栏，
  二维码从「连接地址」卡移到「配对码」卡并放大；顺带修复二维码位图按 160dpi 标记
  被 ImageView 缩小的问题。盒端 1.6.8 已装机验证，截图 cv2 解码通过。

- 2026-10-22 布局修订（用户反馈）：二维码属于「连接地址」版块，移回该卡；
  两栏高度不平齐不美观，改为布局完成后统一两栏总高度、底边对齐；
  宽屏改为左栏「服务状态 + 配对码 + 版本更新」、右栏「连接地址（含二维码）」，
  配对码卡与地址卡吸收剩余高度。版本升至 1.6.9（versionCode 13）。

## 背景与目标

盒端界面为单列纵向卡片：标题 → 服务状态 → 配对码 → 连接地址（含二维码）→ 版本更新。
在电视/DeX 等宽屏上，内容高度超过首屏，二维码落在可视区域下方；部分设备滚动后
会跳回顶部，导致扫不到码。

目标：宽屏下把二维码放到首屏内并保留其与「连接地址」的归属关系；两栏等高、底边平齐；
手机竖屏保持单列，必要时仍可滚动。

## 功能需求（FR）

- FR-33-1 屏幕宽度 >= 720dp 时采用左右两栏：左栏「服务状态 + 配对码 + 版本更新」，
  右栏「连接地址（含二维码与扫码提示）」。
- FR-33-2 二维码显示在「连接地址」卡内、地址文字下方居中，白底圆角容器；
  手机竖屏同样位于该卡。
- FR-33-3 二维码边长：宽屏上限 220dp、窄屏上限 240dp，且不超过屏幕高/宽的五分之二。
- FR-33-4 二维码位图按屏幕密度标记，ImageView 按实际像素 1:1 显示，不被缩小。
- FR-33-5 无网络时二维码与扫码提示一起隐藏，逻辑不变（SPEC-024）。
- FR-33-6 宽屏两栏总高度一致、底边平齐：至少占满首屏可用高度，剩余高度由配对码卡
  与连接地址卡吸收；内容确实超高时整页滚动，二维码仍位于右栏顶部。
- FR-33-7 窄屏（<720dp）保持单列顺序：标题 → 状态 → 配对码 → 地址（含二维码）→ 更新 → 提示；
  配对码字号 48sp，保证六位数字单行显示（宽屏 64sp）。

## 非功能需求（NFR）

- NFR-33-1 二维码内容仍为 `http://<IP>:17880/#pair=<配对码>`，编码逻辑不变。
- NFR-33-2 不引入新依赖，不改变服务状态、配对码、更新按钮的刷新逻辑。
- NFR-33-3 两栏等高只在首次布局后计算一次，不参与每次定时刷新。

## 验收标准

- [ ] AC-1 电视/宽屏首屏内可直接看到配对码与完整二维码，无需滚动。
- [ ] AC-2 截图或实拍中的二维码可被手机相机/解码库识别，内容含当前 IP 与配对码。
- [ ] AC-3 宽屏左右两栏底边平齐，配对码与二维码在各自卡片内居中/顶部对齐自然。
- [ ] AC-4 手机竖屏（<720dp）布局为单列，二维码位于连接地址卡内且完整显示。
- [ ] AC-5 服务状态、配对码、地址、版本更新、二维码显隐与改动前一致。

## 边界与已知限制

- 极低分辨率（如 720x480）下二维码受屏幕宽高五分之二限制，尺寸会缩小。
- 滚动跳回顶部属个别盒子/桌面的输入行为，本次通过“首屏可见”规避，未单独修复滚动逻辑。

## 实现映射

- `server/src/com/koco/tvremoteserver/MainActivity.java`：
  `buildUi()` 宽屏双栏（左：状态/配对码/更新，右：地址/二维码），
  `fitColumns()` 首帧后统一两栏高度并用 `fill()` 让配对码卡、地址卡与配对码文本占满剩余空间；
  `qrBitmap()` 宽屏上限 220dp、按屏幕密度标记。
- `server/res/values/strings.xml`、`values-en/strings.xml`：新增配对码使用提示 `ui_pair_hint`。
