# SPEC-033 盒端界面宽屏双栏与二维码前置

## 元信息

- 状态：developing
- 创建：2026-10-22
- 更新：2026-10-22（实现完成）
- 优先级：high

## 变更记录

- 2026-10-22 创建并实现：用户在电视上查看 Fold3 盒子端界面时，二维码在首屏之外，
  向下滚动后界面又跳回顶部，无法扫码。改为宽屏（>=720dp）左右两栏，
  二维码从「连接地址」卡移到「配对码」卡并放大；顺带修复二维码位图按 160dpi 标记
  被 ImageView 缩小的问题。盒端 1.6.8 已装机验证，截图 cv2 解码通过。

## 背景与目标

盒端界面为单列纵向卡片：标题 → 服务状态 → 配对码 → 连接地址（含二维码）→ 版本更新。
在电视/DeX 等宽屏上，内容高度超过首屏，二维码落在可视区域下方；部分设备滚动后
会跳回顶部，导致扫不到码。

目标：宽屏下把二维码放到首屏内、与配对码同卡并加大尺寸；手机竖屏保持单列，
必要时仍可滚动。

## 功能需求（FR）

- FR-33-1 屏幕宽度 >= 720dp 时采用左右两栏：左栏「服务状态 + 配对码（含二维码）」，
  右栏「连接地址 + 版本更新 + 提示」。
- FR-33-2 二维码移入配对码卡：宽屏在配对码下方居中显示，手机竖屏在配对码下方居中显示。
- FR-33-3 二维码边长：宽屏上限 300dp、窄屏上限 240dp，且不超过屏幕高/宽的五分之二。
- FR-33-4 二维码位图按屏幕密度标记，ImageView 按实际像素 1:1 显示，不被缩小。
- FR-33-5 无网络时二维码与扫码提示一起隐藏，逻辑不变（SPEC-024）。
- FR-33-6 窄屏（<720dp）保持单列顺序：标题 → 状态 → 配对码/二维码 → 地址 → 更新 → 提示。

## 非功能需求（NFR）

- NFR-33-1 二维码内容仍为 `http://<IP>:17880/#pair=<配对码>`，编码逻辑不变。
- NFR-33-2 不引入新依赖，不改变服务状态、配对码、更新按钮的刷新逻辑。

## 验收标准

- [ ] AC-1 电视/宽屏首屏内可直接看到配对码与完整二维码，无需滚动。
- [ ] AC-2 截图或实拍中的二维码可被手机相机/解码库识别，内容含当前 IP 与配对码。
- [ ] AC-3 手机竖屏（<720dp）布局为单列，二维码完整显示未裁切。
- [ ] AC-4 服务状态、配对码、地址、版本更新、二维码显隐与改动前一致。

## 边界与已知限制

- 极低分辨率（如 720x480）下二维码受屏幕宽高五分之二限制，尺寸会缩小。
- 滚动跳回顶部属个别盒子/桌面的输入行为，本次通过“首屏可见”规避，未单独修复滚动逻辑。
