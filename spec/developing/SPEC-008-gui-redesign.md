## 背景与目标

两个 APK 目前无应用图标（显示系统默认机器人图），手机端 UI 为 v1.0 快速实现的扁平布局，
报错信息直接显示原始异常消息（截断 26 字符，如 "Connection refused"），用户无法据此
自行解决问题。本 spec 对两端做整体 GUI 设计：双端应用图标（同族但可区分）、手机端
布局重新设计、盒子端 UI 美化、报错文案体系（发生了什么 + 怎么办）、手机/平板多尺寸适配。

## 功能需求（FR）

### 资源体系与构建
- FR-8-1 两模块新增 `res/` 目录；build.py 增加 `aapt2 compile --dir` 资源编译步骤
  （res 不存在时跳过），link 时把编译产物传入，构建流程其余步骤不变。
- FR-8-2 双端 manifest 中 application 与 activity 的 label 改用 `@string/app_name`，
  application 增加 `android:icon="@mipmap/ic_launcher"`。
- FR-8-3 图标提供五档密度：mdpi 48px / hdpi 72px / xhdpi 96px / xxhdpi 144px / xxxhdpi 192px。

### 图标
- FR-8-4 手机端图标：深色底（#0B0F14 到 #182029 渐变）+ 遥控器图形（方向十字 + 中央
  圆点），蓝色 #2563EB 点缀，扁平现代风，无文字。
- FR-8-5 盒子端图标：同色系深底 + 机顶盒图形 + 蓝色信号波纹；与手机端同族、图形可区分。
- FR-8-6 盒子端通知栏小图标改用自有 `@drawable/ic_stat`（单色剪影），不再用系统
  ic_menu_compass。

### 手机端布局（重新设计；纯 Java 构建；键位 keycode 与三模式分发语义不变）
- FR-8-7 头部区：左侧设备名（大字，点击弹设备选择器）+ 状态徽标（彩色圆点 + 状态文字）。
- FR-8-8 模式区：三段胶囊选择器「直连 / ADB / 蓝牙」，当前模式段高亮填充；段点击行为：
  直连 = 进入直连流程（已配对则直接启用直连，长按清除配对重新配对）、
  ADB = 切回 ADB 模式并重连、蓝牙 = 初始化蓝牙 HID；同行提供「扫描」「添加」按钮。
- FR-8-9 导航区：居中十字键（上左OK右下），OK 为蓝色圆形大按钮。
- FR-8-10 系统键区：返回(4)/主页(3)/菜单(82)/电源(26，红色调) 一行，
  音量+(24)/音量-(25)/静音(164) 一行，keycode 与现有完全一致。
- FR-8-11 输入区与应用区：单行输入框 + 发送（空文本不发送、发送后清空）；
  六个应用快捷按钮（包名与现有完全一致）。
- FR-8-12 视觉规范：8dp 间距网格、16dp 圆角、按键最小高 48dp、RippleDrawable 触摸
  反馈、深色配色体系延续（#0B0F14 底 / #2563EB 强调 / #182029 键面）。
- FR-8-13 多尺寸三档（按 screenWidthDp）：
  - <360dp 紧凑：方向键 56dp、功能键高 44dp、外边距 10dp；
  - 360-599 标准：方向键 64dp、功能键高 52dp、外边距 14dp；
  - >=600 平板：方向键 88dp、功能键高 56dp、外边距 24dp、内容区最大宽 520dp 居中。
  横屏不做独立布局，超屏内容依赖 ScrollView 滚动。

### 报错文案体系
- FR-8-14 新增异常到本地化文案的映射，句式统一「发生了什么 + 怎么办」，至少覆盖：
  主机不可达/连接超时、连接被拒绝、配对码错误（ERR badcode）、配对失效（ERR auth）、
  蓝牙未就绪/不可用、未知异常（附简短原因）。
- FR-8-15 所有 Dialog/Toast/状态栏固定文案改为字符串资源引用，不再硬编码中文。
- FR-8-16 原始异常消息保留为状态栏补充明细（次要信息），超长省略。

### 盒子端 UI
- FR-8-17 信息结构不变（标题/服务状态/root 状态/配对码/本机地址/操作提示），
  视觉升级：配对码大卡片、状态徽标、间距与配色和手机端规范统一，文案资源化。

## 非功能需求（NFR）

- NFR-8-1 UI 仍为纯 Java 构建，无 XML layout，与手工编译链兼容（SPEC-004）。
- NFR-8-2 零第三方依赖；RippleDrawable 为平台 API（API 21+），minSdk 26 可用。
- NFR-8-3 键位 keycode、设备管理持久化格式、三模式分发行为与 SPEC-001/002/003 完全一致。
- NFR-8-4 代码与文档不使用 emoji；界面符号仅限几何字符（上三角、左箭头、圆点等）。
- NFR-8-5 构建后 APK 保持单文件，新增图片资源总量 < 200KB。

## 验收标准

- AC-1 双端构建成功（`python build.py app` / `python build.py server`），资源编译无报错。
- AC-2 launcher 中双端图标显示正确、同族可区分；盒子端通知栏显示自有小图标。
- AC-3 新布局完整：头部/三段模式/十字键/系统键两行/输入/应用六宫格全部可见可点。
- AC-4 三段模式选择器切换行为正确：直连配对与长按清除重配、ADB 切换重连、蓝牙初始化。
- AC-5 三档屏幕宽度下布局不破、按键可点（真机手机 + 平板宽度验证）。
- AC-6 错误场景文案清楚可执行：断网按键、错误配对码、盒子端服务未运行、不存在 IP。
- AC-7 SPEC-003 手工清单关键项回归通过（按键分发、设备持久化、输入发送）。
- AC-8 协议回归 `run.ps1` 全绿（0 失败；用例数 43→41 因 SPEC-011 短连接改造删减 2 条旧断言）。

## 边界与已知限制

- 不做独立横屏布局，横屏超屏内容依赖滚动。
- 图标为静态 PNG，不做自适应图标（adaptive icon）与主题图标。
- 原始异常消息为英文技术文本，仅作次要明细展示。
- 蓝牙模式仍为实验性（SPEC-005 未打通），呈现层不改变其行为。
