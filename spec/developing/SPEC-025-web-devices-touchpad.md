## 背景与目标

Web 遥控页（SPEC-020）目前只服务页面所在的盒子，token 存在当前源下；换一台盒子
必须手动改地址并重新配对。手机端（SPEC-023）已有触控板，网页端只有陀螺仪飞鼠，
而浏览器陀螺仪依赖 HTTPS 与授权，HTTP 页面完全不可用，体验不如手指触控板。

目标：

1. 网页记住连接过的盒子，可切换、可删除，通过盒子二维码扫码快速添加；
2. 网页提供与手机端一致的触控板（拖动、点按、长按、拖动按住、双指滚动）；
3. 删除网页飞鼠，只保留触控板，减少 HTTP 页面上的无效入口；
4. 电源按钮用红色文字强调，降低误触风险。

## 功能需求（FR）

- FR-25-1 设备列表存储：`localStorage` 键 `tvremoteweb_devices` 存 JSON 数组，
  元素 `{"base":"http://ip:17880","name":"ip","token":"..."}`；当前设备存
  `tvremoteweb_current`（值等于某个 `base`）。首次升级时若只有旧键
  `tvremoteweb_token`，把它迁移为当前页面 origin 的设备条目。
- FR-25-2 设备切换：顶部显示当前设备栏，点击弹出网页自绘设备面板（遮罩 + 深色卡片），
  列出全部设备并标记当前项；点击其它设备即切换。所有 API 请求使用选中设备的
  `base` 绝对地址，token 使用该设备自己的 token；切换后立即 ping，失败显示离线，
  401 则清除该设备 token 并回到配对卡。
- FR-25-3 扫码添加：设备面板提供「扫码添加」。页面处于安全上下文且浏览器支持
  `BarcodeDetector` 与 `getUserMedia` 时打开相机识别二维码；识别到
  `http(s)://host:port/#pair=<6位码>` 后向该地址执行配对，成功则加入设备列表并切换。
  不满足条件时隐藏扫码按钮，保留手动添加并提示原因。
- FR-25-4 手动添加：输入盒子地址（可省略协议与端口，默认 `http` 与 `17880`）
  和 6 位配对码；配对成功后加入列表并切换为当前设备。
- FR-25-5 删除设备：设备面板每行提供删除；删除当前设备后切换到列表首个设备，
  列表为空时回到配对卡。删除同时移除该设备 token。
- FR-25-6 二维码直达：用系统相机扫描盒子二维码打开目标盒子页面（带 `#pair=`）时，
  页面把自身 origin 加入/更新设备列表并完成配对（沿用 SPEC-024 的自动配对）。
- FR-25-7 跨源访问：`WebServer` 所有响应返回
  `Access-Control-Allow-Origin: *`、`Access-Control-Allow-Methods: GET, POST, OPTIONS`、
  `Access-Control-Allow-Headers: X-Token, Content-Type` 与
  `Access-Control-Allow-Private-Network: true`；`OPTIONS` 预检返回 204 且不要求 token。
  鉴权仍由 token 与配对失败锁定保证。
- FR-25-8 输入方式切换：遥控卡标题行下方增加「方向盘 / 触控板」分段控件，
  两段等宽；触控板宽度铺满卡片内容区，与系统键行 / 音量行等宽，高度沿用方向盘
  （390px 下 236px，320px 下 208px），方向盘尺寸与位置不变；选择存 `localStorage`
  键 `input`（`dpad` / `touchpad`），默认 `dpad`。
- FR-25-9 触控板手势（与 SPEC-023 直连语义一致）：
  - 单指拖动超过 8px 后按 1.5 倍增益发送相对位移；位移 20ms 合并发送，单轴按 ±127
    分段，不丢位移；进入拖动时先发 `MCLICK 1`，结束时发 `MCLICK 0`；
  - 未超过 8px 抬起发 `MTAP`；两次点击间隔小于 300ms 按两次单击发送；
  - 按住 500ms 未移动、随后抬起发 `MLONG`；
  - 第二指落下退出点击/长按/拖动（已按下先释放），进入双指滚动：
    两指平均 Y 每 24px 记 1 格，两次发送至少间隔 100ms，单次 ±5；
  - 进入触控板先发 `MOVE 0 0` 让盒子显示光标；切回方向盘、页面隐藏、切换设备、
    离线或请求失败时必须释放未完成的按压；切回方向盘另发 `MHIDE` 立即隐藏光标。
- FR-25-10 Web API 扩展：新增 `POST /api/tap`（`MTAP`）、`POST /api/long`（`MLONG`）、
  `POST /api/scroll`（请求体 `{"steps":1}`，`SCROLL`）、`POST /api/hide`（`MHIDE`）；
  沿用 SPEC-020 的鉴权、错误码透出与 `no-store` 规则。
- FR-25-11 删除网页飞鼠：移除飞鼠按钮、陀螺仪监听与采样、飞鼠相关文案与
  OK 键的 `MCLICK` 分支；`MOVE`/`MCLICK` 协议与盒端光标保留（手机端触控板使用）。
- FR-25-12 电源按钮文字改为红色 `#FF5A5A`，图标、边框与其它按键颜色不变。
- FR-25-13 外壳文件（`index.html`、`app.js`、`style.css`、`manifest.webmanifest`、`sw.js`）
  响应不返回可缓存头，盒子升级后页面不会继续加载旧界面；图标仍按 1 小时缓存。
  Service Worker 安装时以 `cache: reload` 拉取外壳并升级缓存版本。
- FR-25-14 设备名称编辑：设备面板每行提供「改名」，点击后就地编辑名称（最多 32 字符），
  回车或失焦保存，Esc 取消；名称写入 `localStorage` 的设备条目，顶部设备栏与列表
  立即更新。名称留空时回落显示地址中的 IP，不影响配对与连接。
- FR-25-15 音量行布局对齐 Android 版：系统键行保持四列（返回 / 主页 / 菜单 / 电源）；
  音量行共用同一四列网格，音量减与音量加之间显示「音量」标签并合并为占前三列的横胶囊，
  静音键独占第四列，与电源键右对齐；行高与系统键一致。
- FR-25-16 切回方向盘时在同一命令队列内补发 `MHIDE`，盒端立即移除光标，
  不等 5 秒空闲回收；方向盘模式下不得残留触控板光标。

## 非功能需求（NFR）

- NFR-25-1 触控板移动端到端延迟在局域网内不超过 100ms；移动请求 20ms 合并，
  不逐点建连刷服务。
- NFR-25-2 设备列表与 token 只写本机 `localStorage`，不上传公网；日志不打印 token。
- NFR-25-3 跨源失败、证书不受信任、混合内容被拦截时页面不崩溃，显示可读提示，
  设备列表保持不变。
- NFR-25-4 兼容 Safari 15+、Chrome 100+、ArkWeb（M114+）、Edge；320px 宽起可用，
  桌面内容仍居中且最大宽度 480px。
- NFR-25-5 不改变 TCP 直连协议语义与手机端行为；现有协议与 Web API 用例保持通过。
- NFR-25-6 触控板失败路径必须释放按压，不得让盒子端触摸卡在按下状态。

## 边界与已知限制

- HTTP 页面不是安全上下文，无法调用相机；页内扫码只在 HTTPS（证书受信任）或
  localhost 下可用。HTTP 页面用系统相机扫码会打开目标盒子自己的页面，
  该页面 origin 有独立设备列表（随后可用页内「手动添加」补录其他盒子）。
- HTTPS 页面请求 HTTP 盒子会被混合内容拦截；跨设备切换时 HTTPS 页面应使用
  `https://host:17843`，且浏览器需信任该盒子自签证书，否则切换会失败。
- 设备列表按浏览器与源隔离，清除站点数据会丢失列表与 token。
- 不提供设备排序、分组、在线状态探测轮询。
- 跨源 CORS 为 `*`：局域网内任何网页都能尝试配对，仍受 6 位码与
  5 次失败锁 5 分钟限制。
- 触控板仍是应用层光标（SPEC-021/023），纯 D-pad 应用可能无响应。
- 不提供右键、中键、横向滚动。
