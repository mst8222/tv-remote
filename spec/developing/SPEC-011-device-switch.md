## 背景与目标

真机发现 bug：直连模式下在设备选择器里把控制目标从盒子 A 切到盒子 B 后，
按键仍然发到 A。根因：直连配对（`lanHost`/`lanToken`）是全局唯一一份，与设备列表
完全脱钩；`switchTo()` 只关闭并重连 ADB，不重建直连连接。

目标：控制目标唯一由「当前设备」决定——任何模式下切换设备，控制对象都随之切换。

## 功能需求（FR）

- FR-11-1 直连配对 token 按盒子 IP 持久化（key `lan_<ip>`），支持多台盒子各自配对
  一次长期有效；不再使用全局 `lanHost`/`lanToken` 键（旧数据启动时一次性迁移到
  `lan_<旧host>` 后删除）。
- FR-11-2 直连模式控制目标恒为当前设备的 IP；状态栏显示的直连地址与实际发送地址一致。
- FR-11-3 直连模式下切换设备：目标设备已配对则立即重建直连并继续直连模式；
  未配对则退出直连回落 ADB 模式并提示（复用 `lan_not_paired` 文案），不弹窗打断。
- FR-11-4 配对成功（`PAIR`）与自动发现到的盒子 IP：若不在设备列表中则自动新增设备并
  切换为当前设备，保证「配对哪台就控制哪台」。
- FR-11-5 长按「直连」清除的是当前设备的配对（`lan_<当前设备IP>`），不影响其他盒子。
- FR-11-6 ADB 模式切换设备行为不变（关旧连接、连新地址）。
- FR-11-7 直连每条命令（KEY/TEXT/APP/PAIR）使用短连接：发前建立、应答即关，
  服务器 30 秒空闲回收不会命中，按键永不出现「连接断开」假失败；
  删除 `LanClient.isConnected()`（短连接后无意义且无调用方）。

## 非功能需求（NFR）

- NFR-11-1 不改动直连报文与服务器行为（`ServerService` / `MockBoxServer` 无需同步），
  仅调整 `LanClient` 连接策略；协议回归必须全绿。
- NFR-11-2 不过度设计：不引入设备详情编辑、不改对话框结构；蓝牙模式与设备列表的
  关系维持现状（SPEC-005 未打通，不扩 scope）。

## 验收标准

- AC-1 直连 A 盒子（已配对）按键生效后，切到未配对的设备 B：自动回落 ADB 模式并提示
  未配对，后续按键发往 B 的 ADB 地址（连接失败时错误信息指向 B）。
- AC-2 从 B 切回已配对的 A：控制目标立即变回 A，按键立即生效；模式跟随用户显式
  选择（切回后处于 ADB 则点直连段直接启用直连，无需重新配对，不弹配对框）。
- AC-3 配对一台列表中不存在的新盒子 C 后，C 自动出现在设备列表且成为当前设备。
- AC-4 长按直连清除配对只影响当前设备，切回其他已配对盒子仍可直接直连。
- AC-5 协议回归 `run.ps1` 全绿（41 用例 0 失败）。
- AC-6 App 重启后各设备的直连配对关系保持（`lan_<ip>` 持久化）。
- AC-7 直连模式下任意按键成功一次，静置超过 35 秒（超过服务器 30 秒空闲回收窗口）后
  再按任意键仍立即生效，状态栏不出现「连接断开」。

## 边界与已知限制

- 蓝牙模式（未打通）不参与本 spec：蓝牙控制目标由系统蓝牙配对决定，与设备列表无关。
- 配对对话框仍允许手填任意 IP；填了非当前设备的 IP 时按 FR-11-4 处理（定位/新增设备）。
- 一次性迁移仅在启动时执行：读到旧全局键就转存并删除，无迁移日志。
