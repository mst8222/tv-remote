## 变更记录
- 2026-10-21 创建：用户要求每台设备默认记住自己最后一次使用的连接方式，
  下次切换到该设备时自动恢复该方式。
- 2026-10-21 实现：`mode_<host>` / `bt_<host>` 按设备持久化，

## 背景与目标

当前连接方式是全局状态：启动固定走直连，蓝牙目标也只记一个全局地址
（`bt_addr`）。多台盒子时，用户每次切换设备都要手动重新点「直连」或「蓝牙」，
且蓝牙模式切换设备后可能仍连在上一个盒子上。

目标：连接方式（直连 / 蓝牙）按设备持久化，切换设备即恢复该设备上次成功
使用的方式；蓝牙目标地址也按设备保存，切换设备时连接目标跟随设备。

## 功能需求（FR）

- FR-15-1 新增持久化键 `mode_<host>`（值为 `lan` 或 `bt`），按设备 IP 保存；
  没有记录的新设备默认 `lan`。
- FR-15-2 只有在连接成功后才写入：直连配对完成或进入已配对的直连时写 `lan`；
  蓝牙 HID 实际连接成功时写 `bt`。
- FR-15-3 启动（`onCreate`）与切换设备（设备选择器、扫描添加、手动添加、
  配对后定位）时，读取目标设备的 `mode_<host>` 并自动恢复：
  - `lan`：已有 token 则直接进入直连；无 token 则高亮直连并提示「还没配对」，
    不自动改走蓝牙。
  - `bt`：重新注册 HID（未注册时）并连接该设备的蓝牙目标；目标缺失或未配对时
    弹设备选择框，选择后记住。
- FR-15-4 蓝牙目标按设备保存键 `bt_<host>`（值为盒子蓝牙 MAC）；设备选择框
  选中的地址写入当前设备的键。删除旧全局键 `bt_addr` 的使用，不做旧数据兼容。
- FR-15-5 从蓝牙设备切到直连设备时，先断开当前蓝牙目标并清空 `btMode`，
  再按目标设备方式恢复，避免按键继续发往上一个盒子。
- FR-15-6 恢复失败不做静默降级：状态栏与模式高亮保持该设备保存的方式，
  并说明具体原因（未配对 / 蓝牙未开启 / 未找到已配对设备），由用户决定改方式。
- FR-15-7 设备删除时清空该设备的 `mode_<host>` 与 `bt_<host>`，避免残留。
- FR-15-8 模式栏高亮始终反映当前设备当前实际使用的连接方式。

## 边界与已知限制

- 蓝牙目标地址与设备 IP 的对应关系由用户选择建立：同一台盒子换 IP 会被视为
  新设备，需要重新选择蓝牙目标。
- 蓝牙连接是异步的，切换设备的瞬间状态栏先显示「正在连接」，连上后显示
  「蓝牙已连接」。
- 记忆的是「最后一次成功使用」的方式，用户手动切换但连接失败时不覆盖记录。
