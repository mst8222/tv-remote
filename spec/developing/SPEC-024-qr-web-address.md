## 背景与目标

SPEC-020 上线后，盒端界面只把网页遥控地址以文本形式显示：
`http://<IP>:17880` 与 `https://<IP>:17843`。用户在手机浏览器里输入 IP 与端口
既慢又易错，且电视画面距离远，读地址本身也困难。

目标：盒端「连接地址」卡内直接显示可扫描的二维码，二维码同时携带配对码；
手机相机扫一下即打开网页遥控并自动完成配对，无需输入地址，也无需再手输
配对码。

## 功能需求（FR）

- FR-24-1 「连接地址」卡内显示二维码，内容为
  `http://<本机IPv4>:17880/#pair=<6位配对码>`，与卡片文本中的网页遥控地址、
  配对码一致。
- FR-24-2 二维码为白底黑模块，四周保留 4 模块静区；按屏幕密度取整数倍缩放
  （每模块至少 1 个物理像素），不使用模糊插值；宽度上限 240dp 且不超过屏幕
  高度的五分之二，保证低分辨率盒子也能完整显示。
- FR-24-3 二维码上方显示 13sp `SUB` 提示文案，中文「手机扫码打开网页遥控
  （手机与盒子需在同一 Wi-Fi）」，英文对应翻译。
- FR-24-4 本机无可用 IPv4（未联网）时，隐藏二维码与提示，地址文本保持
  「未连接网络」。
- FR-24-5 二维码生成器为纯 Java、零第三方依赖：字节模式编码（UTF-8）、
  纠错等级 M、版本 1~3 按内容长度自适应；内容超过版本 3 容量（42 字节）
  时不显示二维码。
- FR-24-6 本机 IP 或配对码变化时重建二维码（按二者的组合比较，避免每 3 秒
  轮询重建）。
- FR-24-7 不修改直连协议与手机端行为；Web 页新增的自动配对流程见 FR-24-8。
- FR-24-8 Web 页加载时若地址 hash 中带 `#pair=<6位码>`，自动填入并提交配对；
  成功后清除 hash、直接进入遥控界面，刷新时使用已保存的 token；失败时保留
  配对卡与错误提示，允许手动重输。

## 非功能需求（NFR）

- NFR-24-1 生成与绘制在 UI 线程完成，29x29 规模耗时不超过 10ms，不引入异步。
- NFR-24-2 二维码位图为 ARGB_8888，单块整数像素，扫描识别率与纯色对比度优先。
- NFR-24-3 生成器可在 PC JVM 直接编译运行（不依赖 Android API），便于自动测试。

## 验收标准（AC）

- AC-1 H96 真机：地址卡显示二维码，用手机相机扫码可打开
  `http://<盒子IP>:17880/#pair=<配对码>`，页面自动完成配对并直接进入遥控界面。
- AC-2 自动：`QrCodeTest` 验证尺寸与结构（定位图形、时序图形、暗模块、
  纠错等级 M 的格式信息、静区外无空白），并通过本地解码验证内容正确。
- AC-3 盒子 IP 或配对码变化后，二维码内容随之更新。
- AC-4 盒子未联网时二维码与提示隐藏，只显示「未连接网络」。
- AC-5 二维码在任何分辨率下都完整显示：1080p 首屏不滚动即可见；720x480 下
  滚动到地址卡后完整可见，不被裁切。
- AC-6 `powershell -File tests\protocol\run.ps1` 全部通过（含 QrCodeTest）。
- AC-7 扫码自动配对失败（如配对码已变化）时，页面显示配对卡与错误提示，
  输入正确配对码可完成配对。

## 边界与已知限制

- 二维码只编码 HTTP 地址；HTTPS（飞鼠需要）仍以文本形式显示，避免首次访问
  被自签证书警告拦住。
- 配对码随二维码公开显示，与盒端界面明文展示一致；使用 URL hash（`#pair=`）
  而非查询参数，配对码不会进入 HTTP 请求行与服务端日志。
- 内容长度上限 42 字节（版本 3 / 纠错 M）；IPv4 地址 + 6 位配对码最多 39 字节，
  固定在此范围内；超过时不显示二维码，不影响文本地址。
- 扫码时若页面已保存旧 token，仍以 hash 中的配对码重新配对（盒子重启后旧
  token 失效）；自动配对失败不做猜测性重试，交回手动输入。
- 不实现二维码解码，不做彩色/带 Logo 样式。
