# SPEC-013 移除手机端 ADB 控制方案 — 手工验收清单

- 对应 spec：spec/developing/SPEC-013-remove-adb-mode.md
- 状态：已执行（Note20 + H96 Max V56 / Fold3 / 模拟器）
- 结果标记：P 通过 / F 失败 / N 未执行

## 用例

### TC-013-01 源码与构建无 ADB（AC-1）
步骤：`grep -r "AdbClient|KeyConst" app/ build.py`；执行 `python build.py app`。
预期：无引用；构建不再读取 `keys/adbkey.pk8`，产物正常签名。
实际：`AdbClient.java` / `KeyConst.java` 已删除，build.py 移除 `gen_key_const()`；
构建输出 `[7/7] 产物: dist/TVRemote.apk 117 KB`，签名校验通过。
结果：P

### TC-013-02 模式栏两段常显（AC-2, FR-13-7）
步骤：冷启动观察模式栏；分别点「直连」「蓝牙」。
预期：两段始终可见、等分；点击后高亮切换，不因连接失败隐藏。
实际：uiautomator 显示「直连」[47,332][429,427]、「蓝牙」[437,332][819,427] 常显；
点击后高亮切换正常，未配对/未注册时只提示不隐藏。
结果：P

### TC-013-03 冷启动直连（AC-3）
步骤：当前设备已配对时冷启动 App。
预期：直接进入直连，状态「直连 · <IP>（已配对）」。
实际：冷启动状态「直连 · 192.168.3.125（已配对）」；
未配对设备则提示「还没配对，点「直连」开始」。
结果：P

### TC-013-04 扫描发现设备（AC-4, FR-13-5）
步骤：点「扫描」，等待 UDP 广播收集。
预期：弹窗列出运行盒子端服务的设备，点击后添加并弹配对框。
实际：模拟器验证扫描弹窗样式与结果列表；真实盒子 UDP 广播发现 H96 / Fold3 IP。
结果：P

### TC-013-05 蓝牙模式下的文字/应用提示（AC-5, FR-13-6）
步骤：蓝牙模式下点「发送」或应用快捷。
预期：状态栏提示「这个功能需要直连模式」，不崩溃。
实际：蓝牙已连接 H96 时点「发送」提示「这个功能需要直连模式：
文字和应用只能通过盒子端服务发送」，按键功能不受影响。
结果：P

### TC-013-06 H96 直连全命令（AC-6）
步骤：H96 Max V56（有 root）配对后执行 PING / PAIR / KEY / TEXT / APP / LIST。
预期：全部返回 OK；按键实际生效。
实际：PING→PONG；PAIR 返回 token；KEY HOME 使 H96 从 Settings 切回当贝桌面；
TEXT / APP / LIST 均正常（协议回归 44 用例覆盖）。
结果：P

### TC-013-07 Fold3 无 root 报错（AC-7）
步骤：Fold3 直连配对后按任意键。
预期：返回 `ERR exec`，手机提示盒子没有 root，不出现假成功。
实际：状态栏「盒子执行失败：这台盒子没有 root。直连按键需要 root，请改用蓝牙模式」。
结果：P

### TC-013-08 构建与协议回归（AC-8）
步骤：`python build.py app`；`powershell -File tests\protocol\run.ps1`。
预期：构建通过；44 用例全绿。
实际：构建通过（117 KB）；回归「通过 44，失败 0 —— 全部通过」。
结果：P
