# SPEC-011 直连目标跟随设备切换 — 手工验收清单

- 对应 spec：spec/developing/SPEC-011-device-switch.md
- 结果标记：P 通过 / F 失败 / N 未执行
- 环境：真机三星 Fold3 + 盒子 A（192.168.3.125，已配对，音量可观测）

## 用例

### TC-011-01 直连 A 后切到未配对设备（AC-1）
步骤：
1. 直连模式按键确认控制 A（音量 13→12）；
2. 点设备名 → 选择未配对的「三星 Fold3 · 安卓13」（192.168.3.38）；
3. 观察状态栏，随后按音量−。
预期：自动回落 ADB 模式；按键发往 B 的 ADB 地址，A 盒音量不变。
实际：切换后状态栏报「操作失败：握手失败」（B 无 adbd 5555，即 ADB 正在连 B）；
向 B 按音量−，A 盒音量 11→11 保持不变——控制目标已切换。　结果：P

### TC-011-02 切回已配对盒子（AC-2）
步骤：从 B 切回 A，点「直连」段，按音量−。
预期：按键立即生效；点直连段直接启用直连（A 已配对），不弹配对框。
实际：切回 A 后 ADB 模式「已连接 · H96_Max_V56」；点直连段直接启用直连
（未弹配对框），音量 11→10 生效。模式跟随用户显式选择，符合 spec 调整后的 AC-2。　结果：P

### TC-011-03 配对新盒子自动入列（AC-3）
步骤：点「直连」→ 配对一台不在设备列表中的盒子 C。
预期：C 自动加入设备列表并成为当前设备，直连直接可用。
实际：N（真机无第二台盒子；曾用 PC 临时假盒子验证，因手机 UI 自动化 IME
不可靠止损，代码路径 focusDevice 与 AC-1/AC-2 共用已验逻辑，留用户有
第二台盒子时确认）　结果：N

### TC-011-04 长按清除只影响当前设备（AC-4）
步骤：长按「直连」清 A 配对 → 切到已配对 C 直连可用 → 切回 A 需重新配对。
预期：lan_<ip> 只删了 A 的。
实际：N（同 TC-011-03，需第二台盒子）　结果：N

### TC-011-05 协议回归（AC-5）
步骤：`powershell -File tests\protocol\run.ps1`。
预期：41 用例 0 失败。
实际：41 用例 0 失败全绿（用例数 43→41：删除旧长连接策略断言
closed_after_close、kick_first_cmd_fails，改写为短连接语义）　结果：P

### TC-011-06 重启保持（AC-6）
步骤：`am force-stop` 杀掉 App 重开 → 点「直连」段 → 按音量−。
预期：各设备直连可直接恢复，无需重新配对。
实际：重启后点直连段直接启用（状态「直连 · 192.168.3.125（已配对）」，
未弹配对框），音量 10→9 生效；旧全局配对键已自动迁移为 lan_192.168.3.125。　结果：P

### TC-011-07 空闲断连不再假失败（AC-7）
步骤：直连按键生效后静置 36 秒（超过服务器 30 秒空闲回收窗口）再按音量−。
预期：立即生效，状态栏不出现「连接断开」。
实际：静置 36 秒后按键 12→11 立即生效（修复前：同场景报「连接断开，
已自动重连，请再按一次」且音量不变）。　结果：P
